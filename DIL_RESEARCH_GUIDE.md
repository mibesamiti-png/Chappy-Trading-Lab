This supplement extends [DEVELOPMENT_WORKFLOW.md](DEVELOPMENT_WORKFLOW.md) without replacing it, [RESEARCH_CHARTER.md](RESEARCH_CHARTER.md), [AUTONOMY_RULES.md](AUTONOMY_RULES.md), the current queue, claims or existing gates. Read the current versions first. If conflicting or missing, follow the authoritative rules and stop at the unresolved boundary. No ABCD, new lab, scheduler, separate ledger, additional approval hierarchy or automatic permission.

## 1. Choose a worthwhile research question (CTL adaptation of DIL-02/10)

Work only on the highest-priority ready, claimed task within its approved scope. An AI may propose hypotheses autonomously; proposing a new question, or receiving "continue", is not approval to expand scope. A null result is successful science when well supported.

Before choosing an experiment:
- Recover the relevant prior hypothesis, protocol, data lineage, negative results and limitations from the existing local evidence/index; label reported-but-unverified material as such. Search by task/question, target, horizon, data version and test family, not only by similar titles. No search hit is not proof of novelty.
- State the scientific question, competing explanations (including measurement/selection artifact and null), observable consequence and what would falsify it. Distinguish direction, magnitude of variation and observed activity. Do not infer price predictability, causality or economic viability from a different target.
- Reject candidates that cannot be identified from available authorized observations, violate the current data scope, depend on unavailable inputs, repeat the same question without new evidence, or exceed the frozen budget. Rank remaining candidates qualitatively by information gained, discriminating power, uncertainty reduced, reuse and cost. Prefer a cheap test that separates explanations; no invented numerical priority scores or forced hypothesis quota.
- Before comparison freeze the protocol, authorized development split, sampling/exclusions, target and baseline, effect-size/uncertainty and multiplicity rules, negative controls, acceptance/stop criteria and finite search budget in the existing record. Record why the next method is sufficient. New hypotheses prompted by results are exploratory and consume the approved budget; do not silently add them to the confirmatory family.

Minimal local record (reuse existing protocol, not a new file per field): question / alternative explanations / prior evidence / discriminating test and baseline / fixed acceptance and stop / scope and budget / decision. If current evidence already answers the question, close it without rerunning.

## 2. Exception-only self-audit: evidence → value → method → arrival (DIL-10 candidate)

Use the existing workflow's audit only on a contradictory control, repeated fix, ambiguous interpretation, unnecessary complexity, no material gain, simpler method discovered or apparent completion. Normal progress requires no extra report. One decision at a time; start with one cheap discriminating check, then only required follow-up. Do not audit the audit.

| Question | Trading Lab application (new CTL-specific guidance) |
|---|---|
| Evidence: is the instrument measuring the intended quantity? | If a surprising effect conflicts with a known control, suspend claims and changes premised on it. On permitted synthetic inputs check an analytical zero/null and known nonzero effect; add equivalent-representation cases (e.g. row order under documented sort, duplicate/missing-bar handling), boundary/session and deliberately leaked future-feature controls when relevant. Check units, denominator, index alignment, target horizon, effective sample size, and whether independently implemented reference logic measures the same estimand. Null controls need not yield exactly zero in stochastic samples. |
| Value: does the difference matter for this question? | Separate statistical significance from absolute effect, uncertainty and the predeclared scientific relevance threshold. Tiny or nonrobust differences need not justify further research. Never choose thresholds after results, invent missing tolerances or waive mandatory checks. If the evidence cannot identify the phenomenon, record the limitation instead of manufacturing stronger claims. |
| Method: is a simpler solution sufficient? | Existing statistics/baselines and local indices → problem decomposition or correct time alignment → existing verified research code → small additional implementation → novel model/algorithm only if simpler alternatives demonstrably fail and scope permits. Splitting by horizon/session or correcting a definition must preserve the intended estimand and dependence structure; no arbitrary dropping of observations or filling missing trades. A complex method is valid if scientifically necessary, not merely because it can be implemented. |
| Arrival: has the scientific objective been reached? | A running script, green CI, passing synthetic tests, fit score and a reproducible scientific conclusion are different things. Confirm the whole analysis pipeline and required controls, uncertainty and limitations. Stop on satisfied completion, supported null, exhausted budget or unidentifiable question; retain failures. A genuine unresolved required test still needs completion or a blocked result. |

Output only when triggered: purpose / contradictory evidence or cost / decision / next action. Choose continue, simplify, reuse, revalidate premise, close current question or request necessary owner judgment. A changed hypothesis/protocol requires the existing authorization rules and a new frozen version; preserve the original results.

## 3. Verify conclusions, not just code

- Check the measurement instrument against known-effect and null fixtures before relying on it. Reuse exact-identity controls already validated for the same definition and input conditions. For an important discrepancy, use a truly independent calculation or analytic reference; another wrapper around the same implementation is not independence. Avoid comparing different estimands.
- Follow the charter's Clean-data audit: noncausal transformations can make real-time inference unidentifiable; shifting bars, cross-validation or a better model does not repair the original information availability. IEX coverage and minute OHLCV limitations remain. Label descriptive results accordingly.
- Compare identical frozen conditions with a relevant competent baseline, report all planned outcomes and dependence-aware uncertainty/multiplicity. Keep synthetic checks, previously consulted development data and genuinely unseen evidence separate. Repeated use of 2024/2025 does not make them fresh holdouts. Independent validation may use synthetic or authorized development evidence, never open reserved 2026 as an audit shortcut.
- For code changes, preserve existing required tests and exact final revision evidence (including actual job scope when applicable). For scientific results, bind local reproducibility to the actual input/version, protocol/config, code, environment and run identity. A hash indicates identity/integrity, not rights, authenticity, absence of leakage or permission.
- Final holdout: **2026 remains LOCKED**; no reading, exploration, feature selection, fitting, tuning, threshold setting, interim evaluation or derived-result inspection from that period as a workaround. Only the existing CTL-006 frozen-protocol and explicit maintainer-approval gate can authorize the single final evaluation. If no justified hypothesis remains, keep it sealed. No post-hoc retuning.

## 4. Efficient autonomy using the existing workflow (DIL-01/03/04–09)

Refresh current main, queue, claim/lease, relevant PR and authoritative rules before selecting work; a short handoff or recent status is not current liveness, input access or writer authority. Use the existing single-writer/lease mechanism; if revision or claim changes, revalidate before acting. Never infer a dead worker from a missing heartbeat or recover a claim outside the existing rules.

Read authoritative sources directly first, then targeted prior evidence/code; expand search on missing facts, conflicts or freeform requests. Use existing indexes, local deterministic scripts and summaries rather than raw market rows in AI context. Do not replace mandatory reads with text search, install a DIL retrieval engine, or create another coordinator. Separate current state from history; preserve old reports rather than repeatedly loading or rewriting them. Reuse only unchanged evidence with matching semantics, code, protocol, data identity and execution scope.

Group comparisons only when the question/invariant, authorization, fixture/oracle, protocol and budget are shared, and retain each outcome and dependence/multiplicity treatment. No combining unrelated hypotheses, duplicate computation, speculative work on blocked tasks, or mandatory case quota. When state changes, invalidate stale preparation; do not repeat setup merely to demonstrate progress. If CI applies, inspect exact-revision summary first, then missing/failed required jobs and only necessary logs; no new CI or altered gates. No assumption that a schedule exists or allowance resets.

Persist once in the existing sanitized handoff/PR after each meaningful task: ID, base/final revision, actual outcome (completed/failed/blocked/unverified), safe evidence pointer, limitations, remaining required gate, next authorized step. Keep detailed scientific data, manifests, hashes of restricted datasets, per-symbol outputs, unreviewed aggregates, models, paths and logs in the authorized local environment; publish only material explicitly safe and permitted. Never upload source or restricted data to public GitHub, CI, issues or PRs, even temporarily. Academic/education only; no trading signals, real-trading algorithms, order/broker integration, commercial transfer or data-source change through this guidance.

## 5. Retain only useful methods

On the next already authorized task, optionally observe readily available actual tool calls, duplicated setup, reruns, user corrections, elapsed time, unnecessary implementation and quality/goal attainment. Count audit overhead. Missing measurements stay unknown, not zero. A shorter text, faster script, CI-to-PR gap or more tests does not prove lower AI usage or better research. Do not create a mandatory telemetry project or infer token/quota savings. If extra audit adds cost without material value, keep the existing simpler workflow; do not remove required evidence or protections.

Use the existing stop rules. Continue authorized ready work only within the current run's scope and capacity; stop at uncertainty requiring judgment, permission boundary, overlap, exhausted budget or no valuable ready task. No new research task is created by this guide.
