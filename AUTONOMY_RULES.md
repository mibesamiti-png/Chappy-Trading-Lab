# Autonomy rules
1. At start read README, ROADMAP, STATE, TASK_QUEUE and HANDOFF from current main. Confirm input access; do not assume Chat and Work share local storage. Do not repeat validated checks without a reason.
2. One active writer per task. Use a dedicated branch and draft PR for changes; claim work in an issue/PR before computation and reconcile current main and open claims. If exclusivity cannot be established, stop rather than race. Main is updated by the maintainer or expressly delegated integrator only; no force pushes.
3. Select the highest-priority ready task whose dependencies are satisfied. Record intended checks, expected outputs and bounded budget. After a task is done, continue to the next ready task if capacity and evidence remain. Stop on exhausted budget, missing permissions, unresolved scientific uncertainty, active overlapping run or no authorized task. Do not invent work to fill time.
4. Save local checkpoints and publish a sanitized status/handoff via PR. Distinguish completed, failed, blocked, and unverified. Preserve evidence and negative results locally. Never report unperformed tests as passed.
5. Keep raw or restricted data, per-symbol results, derived datasets, unreviewed aggregate metrics, manifests, API keys, personal paths and trained artifacts out of public GitHub. .gitignore is defense in depth, not approval. Inspect staged diff and files before publishing; publish only content confirmed safe and permitted by provider. Never upload raw data even temporarily.
6. Academic/education only for HF Data Library. No live trading, brokerage, order placement or real-trading algorithm development using this data. No attempt to evade data terms. Preserve 2026 holdout until frozen protocol and explicit maintainer approval; all exploratory analyses use earlier periods.
7. Scheduled runs: target approximately every five hours only after environment persistence test, avoid overlap, do not assume allowance resets at exact times. On limit or interruption checkpoint and stop; no bypass. No automatic schedule creation here.
8. Human approval required for scope changes, holdout opening, publishing uncertain materials, destructive operations, commercial use, and switching data sources. Report concise meaningful progress, blockers and next task.

9. Every cooperating writer must follow operations/LEASE_PROTOCOL.md: use the one shared coordination branch/file plus a common private local guard, not one lock per worktree. Contents-SHA compare-and-swap and task/protocol idempotency are mandatory. Expiry never authorizes automatic takeover; ownership or budget loss requires checkpoint-and-stop. These safeguards are cooperative and must be integrated into any actual scheduled runner before enabling research.
10. CTL-001 is not complete merely because a fresh subprocess can read a file. Actual intended-agent continuity and tool permissions must be observed. No schedule may be represented as enabled or reliable without its real activation/run evidence.
